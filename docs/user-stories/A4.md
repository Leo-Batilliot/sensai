# A4 — Prompt Versioning

Les prompts sont des artefacts versionnés : chaque version est datée, a un parent et une empreinte, et ne change plus une fois publiée. On choisit la version par configuration (donc on peut revenir en arrière sans toucher au code), et le harness d'évaluation compare deux versions en qualité, latence et tokens.

Chaque critère sera relié à un test ou à un rapport. Tâches : PROMPT-01 (registre), CORE-14 (prompt v2), EVAL-08 (comparaison). Spécification : PROJECT.md §6.11. Contrat : [`docs/contracts/v1.1-extensions.md`](../contracts/v1.1-extensions.md) §3.6. Les critères sont reliés à leurs tests et aux rapports du harness du 30/10 ([`docs/EVALUATION.md`](../EVALUATION.md) §3). Choix technique : [ADR-012](../adr/ADR-012-exemples-fts5-et-prompts-versionnes.md).

## US-A4-01
En tant que **membre de l'équipe**, je veux **comparer deux versions du prompt sur le golden set**, afin de **n'adopter une modification que si elle améliore réellement la qualité**.

**Critères d'acceptation**
- `sensai eval --prompt-version v1` puis une autre version produisent deux rapports, chacun avec le nom, la version et l'empreinte du prompt utilisé.
  — vérifié par : `tests/unit/eval/test_runtime.py::test_report_records_the_prompt_version`, `tests/integration/test_eval_runtime.py::test_the_report_records_how_the_run_was_made`.
- `sensai eval compare` affiche l'écart d'exactitude (EX), de fidélité, de latence et de tokens entre les deux.
  — vérifié par : `tests/unit/eval/test_runtime.py::test_markdown_and_compare_show_categories_tokens_and_memory` (tableau de `compare`) ; chiffres : `eval/reports/2026-10-30_v1.0-qwen3-8b.md` (v1), `…-qwen3-8b-v3.md`, `…-qwen3-8b-v4.md` : à comparaison égale (sans exemples), v1 → v4 : EX 0,58 → 0,74, rappel destructif 0,25 → 1,00 (`…-qwen3-8b-v4-sans-exemples.md`) ; démo : slide « prompts v1 / v3 / v4 » de l'acte 6.
- La décision est écrite dans `docs/decisions.md` avec les chiffres.
  — vérifié par : `docs/decisions.md`, décision D-10 (v4 par défaut, mesures v1, v3, v4 et v4 sans exemples).

**Statut** : fait (PROMPT-01, CORE-14, EVAL-08). Versions publiées : v1 à v4 ; v2 n'a pas eu de run à elle (base de v3 et v4).

## US-A4-02
En tant qu'**admin IT**, je veux **revenir à la version précédente du prompt par une ligne de configuration**, afin de **corriger une régression sans modifier ni redéployer le code**.

**Critères d'acceptation**
- `[agent] prompt_version = "v1"` (ou `SENSAI_AGENT_PROMPT_VERSION=v1`) fait tourner l'agent sur la v1 au démarrage suivant ; une version inconnue est refusée au démarrage avec un message clair.
  — vérifié par : `tests/unit/core/test_prompts.py::test_version_is_chosen_by_config`, `test_unknown_version_is_refused`, `tests/unit/cli/test_app.py::test_unknown_prompt_version_stops_with_exit_code_1`.
- Une version publiée ne peut pas changer en silence : modifier son fichier sans créer de nouvelle version fait échouer les tests.
  — vérifié par : `tests/unit/core/test_prompts.py::test_published_prompts_never_change`, `test_a_changed_file_is_refused`.
- `sensai prompts list` et `sensai prompts diff v1 v4` montrent les versions et leurs différences.
  — vérifié par : `tests/unit/test_cli_entrypoint.py::test_prompts_commands`.

**Statut** : fait (PROMPT-01)
