# A5 — Persona

Le nom, le ton, le périmètre et les **outils autorisés** de l'agent sont définis par profil, dans des fichiers TOML (`personas/`). Trois profils servent le scénario : Contrôle de gestion (Claire : lecture de la base, mémoire et note, aucune écriture SQL ni fichier), ADV (Karim, écritures SQL sous confirmation), Admin (Inès, écriture de fichiers sous confirmation). On change de profil en cours de séance sans perdre l'historique. Un profil ne fait que **restreindre** : il ne lève jamais une confirmation.

Chaque critère est relié à un test (`pytest <chemin>::<test>`, ou test du front `web/src/…`) ou à une étape de démo (actes 1, 4 et 5 de [`docs/keynote/scenario.md`](../keynote/scenario.md)). Tâches : PERS-01 (moteur), WEB-15 (sélecteur). Spécification : PROJECT.md §6.12. Contrat : [`docs/contracts/v1.1-extensions.md`](../contracts/v1.1-extensions.md) §3.1, §3.7, §4. Choix et options écartées : [ADR-009](../adr/ADR-009-profil-restreint-seulement.md).

## US-A5-01
En tant que **responsable ADV**, je veux **passer au profil ADV en cours de séance sans perdre la conversation de Claire**, afin d'**enchaîner sur le nettoyage du fichier clients avec tout le contexte**.

**Critères d'acceptation**
- `/persona adv` en CLI ou le sélecteur de la barre d'état change le profil au tour suivant ; la conversation affichée et l'historique envoyé au modèle sont conservés.
  — vérifié par : côté web (WEB-15), `tests/unit/web/test_ws.py::test_set_persona_changes_the_tools_and_keeps_the_padlocks`, `::test_set_persona_is_accepted_during_a_turn` et `web/src/session/reducer.test.ts` (« profile change ») ; côté moteur (PERS-01), `tests/unit/core/test_personas.py::test_switch_keeps_the_history`, `::test_a_change_during_a_turn_applies_to_the_next_one`, `tests/unit/web/test_real_engine.py::test_a_profile_change_reaches_the_model` et `tests/unit/cli/test_app.py::test_persona_command_switches_and_keeps_the_history` ; démo : acte 4.
- Le changement est visible : badge du profil, séparateur « Profil : ADV (Karim) » dans le fil, message « Profil actif » dans l'historique du modèle.
  — vérifié par : badge et séparateur, y compris après un rechargement, `tests/unit/web/test_ws.py::test_the_profile_change_is_replayed_in_place_after_a_reload` et `reducer.test.ts` (« a reload replays the separator in place ») ; message « Profil actif » de l'historique du modèle, `test_personas.py::test_switch_keeps_the_history` et `::test_several_changes_between_two_turns_give_one_note`.
- Un profil inconnu est refusé (`PERSONA_NOT_FOUND`) sans changer le profil courant.
  — vérifié par : `tests/unit/web/test_ws.py::test_unknown_persona_is_refused`, `test_personas.py::test_unknown_persona_changes_nothing`, `test_app.py::test_unknown_persona_is_refused_and_the_session_goes_on`.

**Statut** : démontrable (WEB-15, PERS-01)

## US-A5-02
En tant que **responsable sécurité**, je veux **que le profil Contrôle de gestion ne puisse jamais modifier les données**, afin que **les droits ne dépendent pas de la bonne volonté du modèle**.

**Critères d'acceptation**
- Les outils d'écriture sont absents de la liste présentée au modèle pour ce profil.
  — vérifié par : `tests/unit/core/test_personas.py::test_tools_are_filtered`, `::test_the_prompt_names_only_the_tools_of_the_profile`, `tests/unit/web/test_real_engine.py::test_a_session_starts_with_the_profile_of_the_configuration`.
- Si le modèle appelle quand même un outil hors profil, la politique le refuse (`TOOL_DENIED`) et rien n'est exécuté.
  — vérifié par : `tests/unit/tools/test_policy.py::test_tool_outside_the_persona_is_denied`, `tests/unit/core/test_personas.py::test_a_tool_outside_the_profile_is_refused_even_if_the_model_calls_it` (un modèle scripté appelle l'outil interdit : refus `TOOL_DENIED`, rien n'est exécuté). L'attaque « escalade de profil » n'a pas été ajoutée aux suites de SEC-02 ([`docs/SECURITY.md`](../SECURITY.md), limites : « pas encore couvert ») : *non fait*.
- Aucun profil ne lève une confirmation : avec le profil ADV, une purge demande toujours la confirmation.
  — vérifié par : `tests/unit/tools/test_policy.py::test_a_persona_never_removes_a_confirmation`, `tests/unit/web/test_real_engine.py::test_set_persona_changes_the_tools_and_keeps_the_padlocks` ; démo : acte 4.

**Statut** : démontrable (PERS-01) ; l'attaque d'escalade manque dans les suites adversariales

## US-A5-03
En tant qu'**intégratrice**, je veux **créer un nouveau profil en ajoutant un fichier**, afin d'**adapter l'assistant à un autre métier sans toucher au code**.

**Critères d'acceptation**
- Un fichier `personas/<id>.toml` valide (nom, rôle, ton, périmètre, outils) apparaît dans `/personas` et dans le sélecteur au démarrage suivant.
  — vérifié par : `tests/unit/core/test_personas.py::test_a_new_file_is_a_new_persona`.
- Un fichier invalide est refusé au démarrage avec un message qui cite le fichier et le champ en cause.
  — vérifié par : `tests/unit/core/test_personas.py::test_invalid_file_is_reported`, `::test_two_files_with_the_same_id_are_refused`, `tests/unit/web/test_server.py::test_web_command_reports_an_invalid_profile`, `tests/unit/cli/test_app.py::test_an_invalid_profile_stops_the_chat`.
- Le ton et le périmètre du profil changent les réponses (un profil refuse poliment une question hors de son périmètre).
  — vérifié par : le bloc du profil remplit le trou `$persona` du prompt v4 (`tests/unit/cli/test_app.py::test_the_chat_announces_the_profile_at_startup`, `tests/unit/web/test_real_engine.py::test_a_profile_change_reaches_the_model`) ; l'effet sur les réponses se vérifie en démo, avec une question hors périmètre posée sous deux profils différents.

**Statut** : démontrable (PERS-01) ; l'effet du ton sur les réponses se vérifie en démo, sans test automatique
