# B1 — Base loop

Chatbot en terminal connecté à un modèle Ollama local : streaming, historique de session, gestion d'erreurs propre, modèle choisi sans toucher au code.

Chaque critère est relié à un test (`pytest <chemin>::<test>`, simulé sans Ollama, lancé par la CI) ou à une étape de démo (`make chat`). Tâches : CORE-02 (client Ollama), CORE-04 (CLI), CORE-05 (moteur).

## US-B1-01
En tant qu'**analyste qui travaille hors ligne**, je veux **discuter avec un modèle local dans mon terminal en voyant la réponse s'écrire au fil de l'eau**, afin de **ne jamais envoyer de données de l'entreprise à un service externe**.

**Critères d'acceptation**
- La réponse s'affiche token par token.
  — vérifié par : `tests/unit/test_ollama_client.py::test_stream_yields_text_then_usage_on_final_chunk`, `tests/unit/cli/test_app.py::test_streams_the_answer_and_records_the_exchange` ; démo : `make chat`, poser une question, le texte apparaît progressivement.
- Une question de suivi (« et le trimestre précédent ? ») est comprise grâce à l'historique.
  — vérifié par : `tests/unit/core/test_engine.py::test_history_is_sent_with_the_next_turn`, `tests/unit/cli/test_app.py::test_second_call_receives_the_first_exchange` ; démo : « Je m'appelle Claire. » puis « Comment je m'appelle ? ».
- `/reset` vide l'historique et le modèle ne se souvient plus de l'échange.
  — vérifié par : `tests/unit/cli/test_app.py::test_reset_empties_the_history`, `tests/unit/core/test_engine.py::test_reset_empties_the_history` ; démo : même échange, `/reset`, puis « Comment je m'appelle ? ».
- Une entrée vide ou faite d'espaces est ignorée avec un message, rien n'est envoyé au modèle.
  — vérifié par : `tests/unit/cli/test_app.py::test_empty_input_sends_nothing` ; démo : appuyer sur Entrée à l'invite.
- `Ctrl+C` pendant une réponse l'interrompt sans quitter ; la réponse partielle est marquée « interrompue » et n'est pas gardée dans l'historique.
  — vérifié par : `tests/unit/cli/test_app.py::test_ctrl_c_during_an_answer_goes_back_to_the_prompt`, `tests/unit/core/test_engine.py::test_cancel_stops_the_turn_at_the_next_chunk` ; démo : `Ctrl+C` pendant une longue réponse.
- Un flux coupé en cours de réponse affiche le texte reçu, marqué interrompu, sans l'ajouter à l'historique.
  — vérifié par : `tests/unit/test_ollama_client.py::test_connection_cut_mid_stream_is_interrupted_with_partial_text`, `tests/unit/cli/test_app.py::test_cut_stream_is_shown_but_not_kept`.

**Statut** : démontrable

## US-B1-02
En tant qu'**admin IT**, je veux **choisir le modèle par argument ou fichier de configuration**, afin de **l'adapter à la machine sans modifier le code**.

**Critères d'acceptation**
- `--model X` prime sur `config.toml`, qui prime sur les valeurs par défaut.
  — vérifié par : `tests/unit/cli/test_app.py::test_model_argument_wins_over_the_config_file`, `tests/unit/cli/test_app.py::test_config_file_model_is_used_without_argument`, `tests/unit/test_config.py::test_cli_overrides_env`, `tests/unit/test_config.py::test_env_overrides_file` ; démo : `python -m sensai chat --model <autre modèle>`, le bandeau de démarrage affiche ce modèle.
- `/model <nom>` change de modèle en cours de session en conservant l'historique.
  — vérifié par : `tests/unit/cli/test_app.py::test_model_command_switches_and_keeps_the_history` ; démo : `/models` puis `/model <nom>`.
- Un modèle absent produit un message qui propose `ollama pull X` et liste les modèles installés.
  — vérifié par : `tests/unit/test_ollama_client.py::test_missing_model_raises_model_not_found_everywhere`, `tests/unit/cli/test_app.py::test_startup_with_a_missing_model_lists_the_installed_ones`, `tests/unit/cli/test_app.py::test_missing_model_stops_with_exit_code_1` ; démo : `python -m sensai chat --model inexistant:1b`.
- Ollama arrêté produit un message clair et la session ne plante pas : il suffit de relancer Ollama et de reposer la question.
  — vérifié par : `tests/unit/test_ollama_client.py::test_unreachable_server_raises_unavailable`, `tests/unit/core/test_engine.py::test_ollama_down_ends_the_turn_with_a_recoverable_error`, `tests/unit/cli/test_app.py::test_session_survives_ollama_being_down`, `tests/unit/cli/test_app.py::test_startup_with_ollama_down_keeps_the_session_open` ; démo : arrêter Ollama, poser une question, relancer `ollama serve`, reposer la question.
- Un modèle qui ne gère pas les outils est signalé dès le démarrage.
  — vérifié par : `tests/unit/cli/test_app.py::test_startup_warns_when_the_model_has_no_tools`.

**Statut** : démontrable
