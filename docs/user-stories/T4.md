# T4 — File Access within Permissions

L'agent lit et écrit des fichiers (exporter la note du comité, lire un fichier d'import) avec ses propres outils (`file_list`, `file_read`, `file_write`), derrière une couche de permissions vérifiée **avant toute opération** : racines déclarées, mode lecture ou lecture-écriture, motifs toujours interdits. Toute écriture demande une confirmation (A3).

Chaque critère est relié à un test ou à une étape de démo (acte 5 de [`docs/keynote/scenario.md`](../keynote/scenario.md)). Tâche : FILE-01 (remplace MCP-08, décision D-03). Spécification : PROJECT.md §6.9. Contrat : [`docs/contracts/v1.1-extensions.md`](../contracts/v1.1-extensions.md) §3.3.

## US-T4-01
En tant qu'**admin IT**, je veux **définir dans la configuration les dossiers que l'agent peut lire ou écrire**, afin qu'**il ne touche jamais à la configuration, aux bases ni aux secrets**.

**Critères d'acceptation**
- Seuls les dossiers de `[[files.roots]]` sont accessibles, avec leur mode (`r` ou `rw`) ; tout le reste est refusé avec un code explicite (`PATH_FORBIDDEN`, `MODE_FORBIDDEN`).
  — vérifié par : `tests/unit/tools/test_file_permissions.py::test_paths` (tableau de chemins acceptés et refusés).
- Les détours sont refusés : `reports/../config.toml`, chemin absolu, lien symbolique qui sort d'une racine, `.env`, `*.db`.
  — vérifié par : `test_paths`, `test_a_link_that_leaves_a_root_is_refused`, `tests/unit/tools/test_file_tools.py::test_reading_the_configuration_is_refused` ; démo : acte 5, « Lis le fichier config.toml » → refus visible dans la timeline.
- Chaque refus est journalisé (`data/file_audit.jsonl`) et la vérification a lieu avant toute ouverture de fichier.
  — vérifié par : `test_file_tools.py::test_every_tool_checks_before_opening`, `test_file_permissions.py::test_refusals_and_writes_are_audited`.

**Statut** : fait (FILE-01)

## US-T4-02
En tant que **contrôleuse de gestion**, je veux **exporter la note du comité dans un fichier Markdown**, afin de **l'envoyer ou de l'imprimer avant la réunion**.

**Critères d'acceptation**
- « Exporte la note du comité dans reports/ » crée le fichier sous `reports/`, après une confirmation qui montre le chemin, la taille et le début du contenu.
  — vérifié par : `test_file_tools.py::test_write_needs_confirmation_and_shows_the_file`, `test_preview_of_a_write` ; démo : acte 5.
- Un refus de la confirmation ne crée aucun fichier ; un fichier existant n'est remplacé que si l'écriture le demande explicitement (`overwrite`).
  — vérifié par : `test_file_tools.py::test_refused_write_creates_nothing`, `test_existing_file_is_kept`.
- Seuls les profils qui ont `file_write` (Admin) peuvent écrire ; les autres n'ont pas l'outil.
  — vérifié par : `tests/unit/core/test_personas.py::test_the_three_profiles_of_the_scenario` (seul Admin a `file_write`), `::test_a_tool_outside_the_profile_is_refused_even_if_the_model_calls_it` ; démo : acte 5, profil Admin.

**Statut** : fait (FILE-01, PERS-01)
