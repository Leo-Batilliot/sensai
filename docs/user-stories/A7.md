# A7 — Automated Prompt Optimization

Le prompt se construit à partir du contexte : pour chaque question, les exemples question → SQL validés les plus proches (recherche FTS5, score bm25) sont injectés dans le prompt, au lieu d'une liste figée. Le gain est mesuré par le harness, sur une banque d'exemples séparée du golden set pour que la mesure reste honnête.

Chaque critère sera relié à un test, à un rapport ou à une étape de démo. Tâches : FEWSHOT-01 (banque, sélection), CORE-14 (`$examples` dans le prompt), EVAL-08 (mesure). Spécification : PROJECT.md §6.16. Contrat : [`docs/contracts/v1.1-extensions.md`](../contracts/v1.1-extensions.md) §2, §3.5. Les critères sont reliés à leurs tests et aux rapports du harness du 30/10. **Résultat mesuré : pas de gain avec qwen3:8b, exemples désactivés par défaut (D-10)**, fonctionnalité livrée et activable par `[fewshot] enabled = true`. Choix technique : [ADR-012](../adr/ADR-012-exemples-fts5-et-prompts-versionnes.md).

## US-A7-01
En tant que **contrôleuse de gestion**, je veux **que l'agent s'inspire de requêtes déjà validées proches de ma question**, afin d'**obtenir un SQL juste plus souvent, surtout sur les filtres de dates et les jointures**.

**Critères d'acceptation**
- Pour chaque question, au plus `k` exemples proches sont injectés, et l'événement `examples_injected` les liste.
  — vérifié par : `tests/unit/core/test_fewshot.py::test_closest_examples_are_selected`, `test_examples_are_injected_and_announced` ; démo : avec `[fewshot] enabled = true`, chip « 3 exemples proches fournis » sous la réponse. Hors de la démo jouée depuis D-10.
- La sélection est déterministe et la question brute n'atteint jamais `MATCH` (requête FTS5 échappée).
  — vérifié par : `tests/unit/core/test_fewshot.py::test_selection_is_stable`, `test_raw_question_is_escaped`.
- Chaque exemple de la banque s'exécute sur la base de démo.
  — vérifié par : `tests/unit/core/test_fewshot.py::test_every_example_runs`.

**Statut** : fait (FEWSHOT-01, CORE-14) ; désactivé par défaut depuis D-10

## US-A7-02
En tant que **membre de l'équipe**, je veux **mesurer le gain des exemples dynamiques sans fuite du golden set**, afin de **prouver que l'amélioration est réelle et non apprise par cœur**.

**Critères d'acceptation**
- Aucune question ni aucun SQL du golden set ne figure dans la banque d'exemples, même reformulé de près.
  — vérifié par : `tests/unit/core/test_fewshot.py::test_no_leak_from_the_golden_set`.
- Le harness compare avec et sans exemples (`fewshot.enabled`) : EX par catégorie, tokens, latence.
  — vérifié par : `eval/reports/2026-10-30_v1.0-qwen3-8b-v4.md` (avec exemples : EX 0,68, 2 tours coupés au délai, tour p95 121 s) contre `…-qwen3-8b-v4-sans-exemples.md` (EX 0,74, aucun tour en erreur, p95 48 s), prompt de 5 312 contre 5 103 tokens ; démo : slide de l'acte 6.
- Le résultat est publié tel quel, gain ou absence de gain.
  — vérifié par : [`docs/EVALUATION.md`](../EVALUATION.md) §3 et `docs/decisions.md` D-10 : l'absence de gain est publiée et montrée telle quelle à l'acte 6.

**Statut** : fait (FEWSHOT-01, EVAL-08) : mesure publiée, sans gain avec qwen3:8b
